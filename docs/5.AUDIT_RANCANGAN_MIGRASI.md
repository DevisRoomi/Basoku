Dokumen ini merupakan hasil audit teknis, analisis kebutuhan data, dan perencanaan skema migrasi database untuk aplikasi **BASOKU**. Dokumen ini disusun berdasarkan empat dokumen perancangan resmi di folder `docs/`:
1. *1.Dokumen Perancangan BASOKU.docx*
2. *2.Data Requirement & ERD BASOKU.docx*
3. *3.DOKUMENTASI DATA HARGA BAHAN BAKSO DAN PEMETAAN KATALOG BASOKU.docx*
4. *4.DOKUMENTASI FORMULA ACUAN, LOGIKA PERHITUNGAN BIAYA, DAN IMPLEMENTASI KALKULATOR BASOKU.docx*

## 2. Pemetaan Lengkap Rancangan Enam Tabel Database

### A. Tabel `users`
* **Fungsi**: Menyimpan akun pengguna, baik pelanggan (*customer*) untuk fitur simpan resep (*My Recipe Lab*), maupun pemilik toko (*admin*) untuk mengelola katalog, resep, dan pesanan.
* **Dasar Keputusan**: Dokumen 1 (Bagian 2 - Role User & Hak Akses) dan Dokumen 2 (Tabel `users`).

| Nama Kolom | Tipe Data Rekomendasi | Atribut / Constraint | Keterangan |
| :--- | :--- | :--- | :--- |
| `id` | `BIGINT UNSIGNED` | `PRIMARY KEY`, `AUTO_INCREMENT` | Pengenal unik akun |
| `name` | `VARCHAR(100)` | `NOT NULL` | Nama lengkap pengguna |
| `email` | `VARCHAR(150)` | `NOT NULL`, `UNIQUE` | Email unik untuk autentikasi |
| `email_verified_at` | `TIMESTAMP` | `NULLABLE` | Standar Laravel Auth (opsional verifikasi email) |
| `password` | `VARCHAR(255)` | `NOT NULL` | Password ter-hash (`bcrypt`) |
| `role` | `ENUM('customer', 'admin')` | `NOT NULL`, `DEFAULT 'customer'` | Hak akses pengguna |
| `remember_token` | `VARCHAR(100)` | `NULLABLE` | Fitur Remember Me Laravel |
| `created_at` | `TIMESTAMP` | `NULLABLE` | Waktu registrasi |
| `updated_at` | `TIMESTAMP` | `NULLABLE` | Waktu pembaruan akun |

## 3. Relasi Antartabel dan Foreign Key Constraints

```
┌──────────────┐          ┌──────────────────────┐
│    users     │          │recipe_configurations │
└──────┬───────┘          └──────────┬───────────┘
       │ 1                           │ 1
       │                             │
       ├──────────────┬──────────────┤
       │ (1:N)        │ (1:N)        │ (1:N)
       ▼              ▼              ▼
┌──────────────┐┌──────────────┐     │
│saved_recipes ││    orders    ├─────┘
└──────────────┘└──────┬───────┘
                       │ 1
                       │ (1:N)
                       ▼
┌──────────────┐┌──────────────┐
│  materials   ││ order_items  │
└──────┬───────┘└──────▲───────┘
       │ 1             │
       └───────────────┘ (1:N, Nullable FK)
```

1. **`users.id` ➔ `saved_recipes.user_id`**:
   * *Relasi*: One-to-Many (`1:N`).
   * *Constraint*: `ON DELETE CASCADE`. Jika akun pengguna dihapus, racikan tersimpan miliknya ikut terhapus.
2. **`users.id` ➔ `orders.user_id`**:
   * *Relasi*: One-to-Many (`1:N`, opsional/nullable).
   * *Constraint*: `ON DELETE SET NULL`. Jika user dihapus, data transaksi pesanan tetap tersimpan untuk keperluan pembukuan omzet admin.
3. **`recipe_configurations.id` ➔ `saved_recipes.recipe_configuration_id`**:
   * *Relasi*: One-to-Many (`1:N`).
   * *Constraint*: `ON DELETE RESTRICT` atau `SET NULL`.
4. **`recipe_configurations.id` ➔ `orders.recipe_configuration_id`**:
   * *Relasi*: One-to-Many (`1:N`, opsional/nullable).
   * *Constraint*: `ON DELETE SET NULL`.
5. **`orders.id` ➔ `order_items.order_id`**:
   * *Relasi*: One-to-Many (`1:N`).
   * *Constraint*: `ON DELETE CASCADE`. Jika data pesanan induk dihapus, rincian bahannya ikut terhapus.
6. **`materials.id` ➔ `order_items.material_id`**:
   * *Relasi*: One-to-Many (`1:N`, opsional/nullable).
   * *Constraint*: `ON DELETE SET NULL`. Karena `order_items` telah menyimpan `material_name` dan `unit_price` secara mandiri sebagai snapshot, integritas riwayat pesanan tetap utuh meskipun bahan di katalog dihapus.

## 4. Analisis Kebutuhan Khusus

1. **Kebutuhan Snapshot Harga Transaksi**:
   * Diatur pada tabel `order_items` (`material_name`, `unit_price`, `subtotal`) dan `orders` (`grinding_fee`, `total_price`).
   * Perubahan harga bahan pada katalog `materials` di masa depan tidak akan mengubah total maupun rincian pesanan yang telah terjadi di masa lalu.
2. **Penyimpanan Detail Resep**:
   * Menggunakan kolom `JSON` pada `saved_recipes.recipe_details`. Ini sangat fleksibel untuk menampung variasi racikan kustom tanpa memerlukan tabel relasi per-item tambahan yang kaku.
3. **Akun Pelanggan dan Admin**:
   * Menggunakan pembeda kolom `role ENUM('customer', 'admin')` pada tabel `users`.
   * Memungkinkan otorisasi berbasis middleware Laravel (`admin` vs `customer`) secara bersih dan terisolasi.

## 5. Hal-Hal yang Belum Pasti dan Perlu Dikonfirmasi ke Penjual

Sesuai instruksi dan fakta Dokumen 2, 3, dan 4, hal-hal berikut **tidak diputuskan secara sepihak**:

1. **Definisi Kolom Rasio di `recipe_configurations`**:
   * Kolom `meat_ratio`, `flour_ratio`, dan `seasoning_ratio` pada Dokumen 2 bertipe `DECIMAL(8,4)`.
   * *Masalah*: Dokumen 4 mencatat bahwa ketiga angka ini belum memiliki rumus matematis resmi (apakah persentase %, pengali, atau indeks bobot), dan belum mampu memetakan belasan rempah bumbu (bawang, garam, merica, penyedap) secara terpisah untuk daging sapi vs ayam.
2. **Penempatan Tarif Jasa Selepan**:
   * Pada Dokumen 2, `grinding_fee` ditaruh di `recipe_configurations`.
   * *Masalah*: Dokumen 2 (catatan asumsi) dan Dokumen 4 menyatakan jika tarif selepan bersifat flat per transaksi atau dihitung per kilogram daging (independen dari preferensi resep), penempatannya perlu dievaluasi.
3. **Dasar Kalkulasi Biaya (Bahan Terpakai vs Pembelian Kemasan Toko)**:
   * Dokumen 3 & 4 menyoroti bahwa pembeli di pasar riil harus membeli dalam kemasan utuh (misal tapioka kemasan 500g seharga Rp9.000, meskipun resep 500g daging hanya memakai 100g senilai Rp1.800). Belum ada keputusan apakah kalkulator menampilkan nilai proporsional bahan terpakai, total uang belanja kemasan, atau keduanya.
4. **Formula Kuantitatif Bumbu "Secukupnya"**:
   * Angka gramatur pasti untuk garam, merica, MSG, penyedap rasa, dan es batu belum ditetapkan dalam angka numerik.

## 6. Strategi Penanganan Migrasi Bawaan Laravel

Untuk menghindari pembuatan ulang tabel atau konflik migrasi pada database `basoku`:
1. **Tabel `users`**:
   * File migrasi bawaan `0001_01_01_000000_create_users_table.php` saat ini membuat tabel `users` (tanpa kolom `role`), `password_reset_tokens`, dan `sessions`.
   * *Strategi Rekomendasi*: Sebelum menjalankan migrasi pertama kali ke database `basoku`, tambahkan kolom `$table->enum('role', ['customer', 'admin'])->default('customer');` langsung pada file migrasi `create_users_table`, ATAU buat file migrasi baru `add_role_to_users_table`. Karena database `basoku` masih kosong, menyelaraskannya langsung pada migrasi `create_users_table` atau menambahkan migrasi terpisah dapat dilakukan dengan sangat bersih.
2. **Tabel `cache` dan `jobs`**:
   * Migrasi bawaan `0001_01_01_000001_create_cache_table.php` dan `0001_01_01_000002_create_jobs_table.php` tetap dipertahankan apa adanya karena menyediakan infrastruktur queue dan cache database bawaan Laravel.
